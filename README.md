## 竞价实例什么时候会被回收？只跟库存有关

腾讯云文档把竞价实例称为波动型竞价实例（Spot），并明确说明：系统不会因为市场价格变化中断实例，只在竞价实例资源库存不足时回收。回收时优先挑出价低的实例，回收后实例数据不保留。

回收通知需要自己订阅。在消息中心订阅“竞价实例回收通知”后，系统会在回收前5分钟发提醒；没订阅就没有这5分钟。另外，实例元数据可以感知即将中断的状态，官方给的最佳实践是在2分钟保留期内把计算结果保存到COS、CFS或NAS。

不适合放竞价实例的任务：数据库服务、没有负载均衡的在线服务和网站、分布式架构里的核心主控制节点、10小时以上的大数据计算作业。

适合的任务：大数据计算、挂了负载均衡的在线服务和网站、网络爬虫、基因测序和分析、药物晶型分析、视频转码和渲染、金融交易数据分析、图片和多媒体处理、科学计算。

网站服务这里有个需要拆开看的地方：官方把“采用了负载均衡的在线服务和网站服务”列为适用场景，但竞价实例不支持ICP备案。需要备案的网站，把备案主体和前端放在其他计费模式的实例上，竞价实例跑不需要备案的后端任务，两边都不耽误。

## 怎么把中断损失压到最低？

思路就一句话：让任务随时能停，停了能续，前端无感。具体做四件事。

第一，订阅回收通知，并把实例元数据接进业务逻辑。5分钟通知加2分钟元数据保留期，足够把内存里的结果刷到持久存储。

第二，切小任务粒度。长作业拆成细粒度作业，减少一次回收带走的进度；用EMR这类天然支持切分的大数据套件更省事。

第三，接入层上负载均衡。后端按“部分按量计费实例+大量竞价实例”配比，监听中断事件，把即将回收的实例从CLB摘掉，前端请求转到健康实例。

第四，中间结果写入持久存储。COS、CFS、NAS都行，重建实例后从上次的断点接着算。别把中间结果只放在竞价实例的系统盘上，回收时一起没。

**竞价实例能跑大模型推理吗？**

能。GN7的16GB显存能覆盖多数轻量和中等规模推理，官方把LLM部署、AIGC、智能客服列在适用场景里；13B–30B的INT8量化模型看GN8的24GB。前提是推理服务做成多实例或挂负载均衡，单机被回收不影响整体。

**被回收后数据能恢复吗？**

不能。实例数据不保留，除非提前把结果写到COS/CFS/NAS，或者做了快照。重要中间结果不要只存在实例盘上。

**为什么价格一直在变？**

竞价价格按市场供需实时变化，区间是同一规格按量价的5%到100%。库存紧张时价格上涨，回收也按价格排序，低价实例先被回收。

**GPU竞价实例支持哪些规格？**
